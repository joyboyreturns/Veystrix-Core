# Experimental model-router work in progress

This code is not the active app launcher and is not ready to be enabled by default. `veystrix.model_router` exposes a model catalog and serializes requests through `ModelCoordinator`, which checks exact installation identity, rejects ambiguous family aliases and protects an owned conversation against a different session's model handoff. `ProcessDriver` launches one guarded engine process group and refuses to load a replacement if the previous group has not exited. Requests are not automatically retried. `harness_models` merges two registry entries into Qwen Code and DeepSeek profile shapes, and `harness_configure` can apply these updates with backups after an explicit action.

A local fake-engine test switched a → b → a through a single endpoint with distinct process groups, and the installed DeepSeek CLI composed a temporary catalog containing both real local model IDs. These are not real-model generation or UI tests. The existing application still starts the single-model supervisor; the router is not connected to the app and the experimental Refresh Harness Models action must not be distributed as a complete switching solution.

Remaining work before enabling: test real supervised Qwen/Nemotron loads and termination under the existing memory/swap/watchdog policies; restore unattended restart supervision; ensure client cancellation and long model-load heartbeats across all API transports; validate session affinity when each real harness changes models, including sessions lacking explicit IDs and auxiliary requests; ensure recoverable state and safe handling of failed loads; implement and verify the Hermes provider refresh; run all three real harnesses; then connect the app launcher, rebuild, launch, and test the installed bundle. Current tests do not establish these guarantees.
