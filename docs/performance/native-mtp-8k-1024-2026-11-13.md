# Native MTP at 8K prompt and 1,024 output tokens

The [previous large code-review comparison](prompt-lookup-and-prefill-2026-11-13.md)
tested the combined performance options. Decode fell from 0.95 to 0.90 tok/s
on Flash-Next and from 4.64 to 3.36 tok/s on Nemotron. Flash-Next used
native MTP in both arms. Nemotron used prompt lookup in the candidate arm.

## Configuration

This comparison uses the local Flash-Next and Nemotron checkpoints, a
repository code-review prompt, greedy decoding, and a request cap of 1,024
output tokens. Each decoder state starts in its own server process and
empty prefix directory. Its warm request repeats the identical prompt in
that process. macOS file caches remain available between arms. Both
checkpoints use the fixed `--pool-gb 2` setting and a 5 GiB absolute
system swap stop. This maps about 2 GB of expert storage in Flash-Next
and budgets 2 GiB in Nemotron. Flash-Next uses BF16 KV and the
short-throughput profile. Nemotron uses INT8 KV. Native MTP uses a draft
depth of two.

The Nemotron target uses the [Sevren affine-Q4 sidecar](https://huggingface.co/sevren-ai/nemotron-3.5-lightning-mtp-head-mlx-4bit)
for the corresponding mlx-community Lightning conversion. The sidecar
is installed at `~/Models/Nemotron-3.5-Lightning-MTP-MLX-4bit`. Revision
`4f543a7223fc85ee731f33c625e800d2e6460cfc` published the weights with
SHA-256 `5dd0e0c942e7f8e4c3fa706cb31e5cce5fe321f271c54b0353546923a6bd54e1`,
which matched the download. The target model verifies every draft.

The macOS app exposes each model's decoder, MTP depth, default output
limit, expert seeding, background prefix writes, affine FMA, and Metal
command buffer sizing in Settings. Nemotron accepts a custom sidecar
folder and has an INT8/BF16 KV precision control. The existing Engine
section exposes decode pool size and swap limit. Changes apply on the
next engine start.

## Measurements

Prefill time is engine time for the uncached input. Time to first text
includes prefix restoration and response streaming. Decode rate measures
generated tokens per engine decode second. The warm rows show the actual
number of input tokens reused by the engine.

| Model | Native MTP | Request | Cached input | Prefill | First text | Decode | Total |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| Nemotron | Off | Cold | 0 / 8,192 | 40.78 s | 41.26 s | 3.90 tok/s | 303.50 s |
| Nemotron | Off | Warm | 8,127 / 8,192 | 4.34 s | 4.76 s | 4.73 tok/s | 220.88 s |
| Nemotron | On | Cold | 0 / 8,192 | 40.10 s | 42.64 s | 2.25 tok/s | 495.00 s |
| Nemotron | On | Warm | 8,127 / 8,192 | 4.19 s | 6.08 s | 2.65 tok/s | 391.14 s |
| Flash-Next | Off | Cold | 0 / 8,192 | 88.02 s | 88.78 s | 2.32 tok/s | 529.47 s |
| Flash-Next | Off | Warm | 8,185 / 8,192 | 2.14 s | 2.69 s | 2.19 tok/s | 469.50 s |
| Flash-Next | On | Cold | 0 / 8,192 | 234.95 s | 238.09 s | 1.17 tok/s | 1,111.28 s |
| Flash-Next | On | Warm | 0 / 8,192 | 339.41 s | 345.38 s | 1.13 tok/s | 1,247.71 s |

All four Nemotron requests generated identical sequences of 1,024 token
IDs. Cold prefill processed 200.91 tok/s with MTP off and 204.27 tok/s
with MTP on. Both warm requests computed the remaining 65 input tokens.
Native MTP reduced decode throughput by 42% cold and 44% warm. Total time
rose 63% cold and 77% warm. The highest sampled swap use was 1,994 MiB
without MTP and 2,495 MiB with it. See
[the raw Nemotron arms](../../results/nemotron35/20261113-051320-context-mtp-8k-1024-manual/context-arms.jsonl).

Both Flash-Next baseline requests generated the same 1,024 token IDs.
The first MTP-on attempt used 243.51 seconds for prefill. The independent
swap watchdog stopped it during decode at 5,141.6 MiB. A second attempt
uses a 512 MiB MLX allocator reuse limit during native MTP prefill and
decode, with the same 2 GB expert pool and 5 GiB swap stop. See
[the baseline and first attempt](../../results/flashnext/20261113-053759-context-mtp-8k-1024-manual/context-arms.jsonl)
and [the MTP retry](../../results/flashnext/20261113-060843-context-mtp-8k-1024-manual/context-arms.jsonl).

Both bounded Flash-Next MTP requests generated the same 1,024 token IDs
as each other. That sequence differs from the standard path. Native MTP
uses a different prefill schedule and bypasses the target-only prefix
snapshots. The repeat request therefore re-prefilled all 8,192 tokens.
Native MTP reduced decode throughput by 50% cold and 48% on replay.
Highest sampled swap use was 2,867 MiB without MTP and 3,958 MiB in the
bounded MTP pair. Each row represents a single request on this Mac.

## Reproduce

Run each checkpoint separately from the Veystrix checkout.

```sh
FLASHNEXT_SWAP_CEILING_MIB=5120 .venv/bin/python \
  -m models.flashnext.tests.bench.bench_server_context_cache \
  --runtime nemotron35 --compare-mtp \
  --checkpoint "$HOME/Models/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-4bit-mlx-community"

FLASHNEXT_SWAP_CEILING_MIB=5120 .venv/bin/python \
  -m models.flashnext.tests.bench.bench_server_context_cache \
  --runtime flashnext --compare-mtp \
  --checkpoint "$HOME/Models/Qwen3.8-Flash-Next-MLX-4bit-MTP"
```
